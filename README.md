# 蓍草

**蓍草**是一个独立开发的传统术数知识库项目。项目目标不是直接进行命理或占筮判断，而是把术数中的基础概念、固定关系、传统文献依据与可计算事实整理成一套可维护、可检索、可复用的知识系统。

当前版本：**v0.1.17**。

第一阶段已经完成共同基础概念、知识条目规范、结构化事实层、独立前台、自动测试与 GitHub Pages 部署。后续将在现有基础上继续扩展四柱命理、六爻等知识分支。

## 项目设计

蓍草把“知识解释”和“固定事实”分开维护。

- `src/knowledge/entries/`：知识条目正文、章节、脚注与参考资料；
- `src/knowledge/data/foundation/`：五行、天干、地支、藏干、六十甲子、十二长生、地支关系、旺相休囚死等稳定结构化事实与推导函数；
- `src/knowledge/runtime/`：Registry、关系解析、引用解析、搜索、校验等运行时能力；
- `src/knowledge/public-api.ts`：知识库对内部组件及未来外部消费者暴露的稳定入口；
- `src/components/knowledge/structuredFactMarkdown.ts`：把 Markdown 中的结构化事实标记转换成展示内容。

固定事实遵循“**一个事实尽量只维护一次**”的原则。例如十二长生不再分别维护总表、十干行表和十二支列表，而是由统一起点与顺逆规则生成；六十甲子由天干、地支顺序同步循环生成；旺相休囚死由五行生克规则推导。

结构化不意味着把所有内容都改成数据。传统术语解释、文献原文、异说、概念边界与条件性说明仍保留在 Markdown 正文中。

## 知识链接与引用

- Knowledge ID 是知识条目的稳定标识；
- 显式 `[[Knowledge ID|显示文字]]` 可用于精确链接或消歧；
- Registry 已登记的知识概念可在正文中自动生成首次链接；
- 当前条目不会自链接；
- 同名概念存在歧义时不会自动猜测；
- 脚注使用稳定引用标记，并由统一引用系统生成参考资料；
- 表格、普通正文和列表使用各自的自动链接去重规则。

所有前台 URL 由 Route Adapter 解析，不把路由形式作为知识事实的一部分。

## 前台

当前前台提供：

- 数据驱动的层级知识目录；
- 首页与全局知识搜索；
- 知识详情页；
- 拼音标题；
- 章节与关系选项卡；
- 稳定脚注和参考资料；
- GitHub Pages 静态部署与 SPA 直达路由回退。

前台不显示 Knowledge ID、条目统计等内部维护字段。

## 本地开发

需要 Node.js 与 npm。

安装依赖：

```bash
npm install
```

启动开发环境：

```bash
npm run dev
```

运行测试：

```bash
npm test
```

运行静态审计：

```bash
npm run audit
```

生产构建：

```bash
npm run build
```

`npm run build` 会执行 TypeScript/Vue 类型检查，并在构建完成后生成 `dist/404.html`，用于 GitHub Pages 等静态托管环境的 SPA 直达路由回退。

若部署到仓库子路径，可在构建时设置：

```bash
VITE_BASE_PATH=/仓库名/
```

## GitHub Pages

仓库使用 GitHub Actions 自动构建并发布 GitHub Pages。正常开发流程只需要提交并推送到 `main`：

```bash
git add .
git commit -m "..."
git push
```

部署工作流会自动完成安装依赖、构建与 Pages 发布。

## 编辑规范

项目的知识内容与代码维护以 `docs/` 中的规范为准。当前规范体系包括项目级编辑规范、天干专项规范、地支专项规范及规范体系索引等。

核心原则包括：

- 先充分研究传统文献，再压缩为清晰正文；
- 正文解释知识，不写成文献综述；
- 当前条目只承担当前概念的知识范围；
- 概念事实与应用判断分层；
- 不为形式整齐强行制造对称结构；
- 引文用于提供证据，不作为装饰；
- 固定事实优先由结构化数据或统一算法维护；
- 不把传统术语直接改写成现代人格或心理标签。

## 与龟甲的边界

蓍草与“龟甲”保持独立：

- 蓍草不引用龟甲代码；
- 蓍草不承担具体排盘或断法计算；
- 龟甲未来可以通过 Knowledge ID、`public-api.ts` 或独立站链接消费蓍草知识；
- 外部应用不应直接依赖 `entries/` 的内部文件结构。
