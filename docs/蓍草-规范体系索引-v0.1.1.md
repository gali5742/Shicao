# 蓍草 · 规范体系索引 v0.1.1

## 1. 规范分层

“蓍草”规范分为三层：

1. **项目架构规范**
   - 规定知识库如何组织、加载、校验、链接、关系解析和向前台暴露。
   - 重点处理 Knowledge ID、Registry、Relation、引用、概念链接、单一事实来源等问题。
   - 不规定某一知识类别具体应写哪些章节。

2. **项目级编辑规范**
   - 规定所有知识类别共同遵守的文献、正文、引用、术语、取象和证据使用原则。
   - 适用于五行、天干、地支、十神、十二长生、六十四卦等整个知识库。
   - 不写某一知识类别特有的内容结构。

3. **分类专项编辑规范**
   - 规定某一知识类别内部的固定知识层级、材料优先级和专项处理规则。
   - 例如：
     - 《蓍草 · 天干条目专项编辑规范》
     - 未来可建立《蓍草 · 地支条目专项编辑规范》
     - 《蓍草 · 十神条目专项编辑规范》
     - 《蓍草 · 十二长生条目专项编辑规范》

## 2. 判断一条规则应放在哪里

### 放入项目架构规范

当规则主要回答：

- 程序如何识别知识？
- 知识事实在哪里维护？
- 概念如何链接？
- 关系如何正反向解析？
- 页面 URL 如何与 Knowledge ID 解耦？
- 如何避免重复数据和死链接？

则放入项目架构规范。

### 放入项目级编辑规范

当规则适用于多数知识类别，例如：

- 如何选择文献；
- 如何保留原典；
- 如何处理现代语义歧义；
- 条件句如何改写；
- 取象与定义如何区分；
- 正文与参考资料如何分工；

则放入项目级编辑规范。

### 放入分类专项编辑规范

当规则只在特定类别成立，例如：

- 天干要比较同五行阴阳两干；
- 天干四时优先寻找“本干本月”材料；
- 天干条目统一包含十二长生；
- 天干页面十神只给结论，不展开排法；

则放入天干专项规范，不上升为项目通用规则。
